## Design Context

### Users

Exawatt serves operators commanding many concurrent agents across compatible local and hosted harnesses. Repeated daily work needs predictable navigation, trustworthy status, recoverable interruptions and efficient keyboard interaction. First-time users should understand the same interface without learning hidden conventions. Demo Mode is a first-class source forever.

This context is subordinate to `docs/engineering/design-system.md`, the product concepts and the singular engineering roadmap. It is not a separate design canon.

### Brand Personality

Commanding, lucid, kinetic.

The interface should feel like a tactical operations console for useful agent work: dense enough for repeated use, clear enough for a first-time walkthrough, and animated enough to feel alive without becoming decorative.

### Aesthetic Direction

Classic, Air and Night share semantic roles and operational meaning. The operator's 2026-10-02 brief is excellent, predictable, clean, understandable and delightful across the app. Spacious overlays and discoverable keyboard actions should fit the existing system; dense operational surfaces retain useful information. Motion explains transitions and honors reduced motion. Delight follows a real accomplishment rather than competing with Agent attention.

### Design Principles

- Orient the user to their current scope and show the next useful action; preserve Agent, Team and Fleet navigation and context.
- Change information resolution with altitude: Fleet summarizes Projects,
  Project reveals named agent units, and Agent reveals focused operational
  detail. Do not enlarge anonymous high-scale marks for the small-fleet demo.
- Treat Demo Mode as a real source, not a fake overlay.
- Make blockers and approvals the hero trust moment.
- Use motion to explain state changes: activity arrival, blocker resolution, heartbeat runs, and source changes.
- Keep copy short, concrete, and operational.
- Share overlay material, focus handoff, shortcut presentation and operation notices; retain each domain's action, lifetime and delivery semantics.
- Preserve drafts while running, freeze submission attempts, and announce actual outcomes without interrupting unrelated work.
