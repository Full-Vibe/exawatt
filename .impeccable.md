## Design Context

### Users

Exawatt's near-term demo audience is potential contributors, collaborators, and early technical evaluators who need to understand the product direction quickly. They are evaluating whether Exawatt can become a serious command layer for agent teams, starting with local OpenClaw-style control and expanding toward hosted and multi-source fleets.

### Brand Personality

Commanding, lucid, kinetic.

The interface should feel like a tactical operations console for useful agent work: dense enough for repeated use, clear enough for a first-time walkthrough, and animated enough to feel alive without becoming decorative.

### Aesthetic Direction

Dark operations UI with precise contrast, status-driven color, and game-like motion for zooming, state changes, and successful interventions. The demo should avoid a marketing-page feel. It should open directly into fleet management and explain itself through operational state, not long instructional copy.

### Design Principles

- Show fleet health first, then let the user zoom into one agent session.
- Treat Demo Mode as a real source, not a fake overlay.
- Make blockers and approvals the hero trust moment.
- Use motion to explain state changes: activity arrival, blocker resolution, heartbeat runs, and source changes.
- Keep copy short, concrete, and operational.
